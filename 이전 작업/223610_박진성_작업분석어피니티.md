## 4. 계층적 작업분석(HTA)

대표 과업:

> 맥도날드 터치스크린 키오스크에서 손주를 위한 버거 세트(빅맥 세트)의 사이드 메뉴를 치즈스틱으로 변경하고 신용카드로 결제를 완료하기

| 번호 | 목표·하위 작업 | 선행 조건 | 정보·도구 | 오류·예외 |
|---|---|---|---|---|
| 0 | 최종 목표: 버거 세트 사이드 변경 및 신용카드 결제 완료 | 키오스크 대기열 통과 및 화면 앞 위치 | 키오스크 스크린, 신용카드, 돋보기안경 | 결제 중도 포기, 대기열 압박으로 인한 이탈 |
| 1 | 주문 시작하기 | 대기 화면 표시 상태 | 화면 상단 광고, 화면 중앙/하단 주문하기 버튼 | 시작 버튼 미인지로 인한 시선 정체(8초 이상) |
| 1.1 | 식사 장소 선택 (매장 식사 / 포장 주문) | '주문하기' 터치 완료 | 매장 식사 / 테이크아웃 아이콘 버튼 | 식사 장소 오선택 (사후 변경 불가 우려) |
| 2 | 메뉴 탐색 및 세트 선택 | 식사 장소 선택 완료 | 카테고리 탭, 버거 썸네일 이미지 및 가격 텍스트 | 카테고리 분류 혼동, 스크롤 미인지 |
| 2.1 | 버거 카테고리 선택 및 대상 버거(빅맥 세트) 터치 | 버거 메뉴 목록 로딩 | 빅맥 세트 메뉴 카드, 가격 정보 | 단품과 세트 메뉴의 시각적 구분 혼선 |
| 3 | 세트 메뉴 세부 옵션(사이드) 변경 | 빅맥 세트 상세 화면 진입 | 기본 구성품(버거, 감자튀김, 콜라), 변경 버튼 | 변경 버튼 미인지로 기본 세트 즉시 장바구니 담기 |
| 3.1 | 사이드 메뉴 변경 화면 진입 | 상세 옵션 화면 활성화 | '사이드 변경' 버튼 (작은 텍스트) | 버튼 크기 부족으로 클릭 실패 또는 지나침 |
| 3.2 | 대체 사이드(치즈스틱) 선택 및 변경 적용 | 사이드 목록 모달 표시 | 사이드 메뉴 썸네일, 추가금액(+0원/+500원 등) | 추가금 계산 혼선, 원하는 메뉴 탐색 지연 |
| 3.3 | 변경된 세트 메뉴 장바구니 담기 | 치즈스틱 선택 완료 | '장바구니 담기' 확인 버튼 | 옵션 변경 취소 또는 미반영 담기 오류 |

## 생성형 AI 활용 실습

먼저 연구자가 Chapter 05의 원자료를 기반으로 1차 어피니티 군집을 구축한 후, 생성형 AI(Gemini)에 메모 ID 목록을 제공하여 대안 군집 및 반대 사례를 탐색하고 사람이 비평·보완했습니다.

| 활용 | 추천 방법 | 사람이 확인할 내용 |
|---|---|---|
| 대안 군집 | 익명 메모 ID만으로 다른 군집안 생성 | 원문 의미 훼손·과도한 통합 여부 확인 (AI가 결제 단절과 하드웨어 조작을 하나로 뭉뚱그린 것을 세부 단계로 분리 유지) |
| HTA 누락 점검 | 사람이 만든 HTA의 선행조건·예외 비평 | 관찰되지 않은 단계는 가정으로 표시하고, 장바구니 삭제 후 재선택하는 예외 루프(Plan 3)가 누락되지 않았는지 점검 |
| 반대 사례 탐색 | 인사이트와 맞지 않는 메모 요청 | 테이블 서비스 기본값 설정 시 소외될 수 있는 이동약자(M24) 및 단순 주문군(M23) 메모 보존 여부 검증 |

추천 프롬프트:

> 아래 24개의 관찰 메모 ID(M01~M23)의 원문을 유지한 채, 고령 사용자의 키오스크 과업 수행 맥락에 맞는 2가지 대안 군집안을 제안하라. 군집 제목은 '사용자는 ___할 때 ___한다' 형태의 행동 패턴 문장으로 작성하고, 어느 군집에도 속하지 않는 예외 사례(M22, M23)를 독립된 반대 메모로 명시하라.

## 9. AI 사용 기록

| 도구 | 사용 목적 | 익명화 방법 | AI 군집·해석 중 거부한 내용 | 원자료와 대조·수정한 결과 |
|---|---|---|---|---|
| Gemini | 어피니티 다이어그램 대안 군집 도출 및 패턴 문장 정제 | 참여자 이름 배제, 메모(M01~M23) 및 발화 요약문만 입력 | "고령자는 키오스크를 무서워하므로 주문 자체를 직원이 대행해야 한다"는 과도한 기술 비관론적 군집안 거부 | 실제 관찰 기록에 근거하여 '버튼 기표 부족'과 '결제 부가 과업의 오류 오인'이라는 구체적 UI/UX 장벽 군집(G01~G05)으로 체계화 |
| Claude | 계층적 작업분석(HTA) 분기 계획 및 As-is/To-be 예외 케이스 검증 | 특정 매장명 및 개인정보 마스킹 처리 | "테이블 서비스를 시스템에서 완전히 삭제하라"는 극단적 단순화 제안 거부 (이동약자 배제 위험) | 기본값은 '카운터 수령'으로 단순화하되, 반대 사례(M23)를 고려하여 테이블 서비스 선택 경로를 옵션으로 유지하는 To-be 플로우로 보완 |
