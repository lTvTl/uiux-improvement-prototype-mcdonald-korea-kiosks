## 2. 사용 맥락과 설계 가정

### 2-1. 사용 맥락

| 관찰 항목 | 기록 |
|---|---|
| 사용자의 신체·인지 특성 | 작은 글씨를 읽기 어렵고, 터치 조작에 익숙치 않치만 간단한 키오스크의 메뉴 구조와 카드 투입 방향에 경험이 있음. |
| 환경 조건 | 주변 안내 방송과 대화 소음이 있으며, 뒤에 다른 중년층의 손님이 대기함. 키오스크가 2대가 있지만 한대가 고장나 있어서 해당 키오스크로만 주문이 가능한 상태. |
| 시간·심리 조건 | 뒤에 손님이 2명 이상 서있는 상태로, 빨리 결제를 끝내야 한다는 압박을 느낌. 또한  |
| 사용 기기·입력 방식 | 대형 터치스크린, 물리적 카드 삽입구, 영수증 출력구 |
| 실패했을 때의 결과 | 결제를 반복하거나 과업을 포기하고 직원에게 도움을 요청하거나 다른 음식점으로 이동함. |

### 2-2. 현재 설계가 전제하는 사용자

> 현재 설계는 사용자가 `키오스크`이라는 기계를 이해했고, 카드의 IC칩 방향과 카드 삽입구 위치를 알고 있다고 가정한다. 또한 작은 안내 문구를 읽고 짧은 시간 안에 다음 행동을 판단할 수 있다고 전제한다.

### 사실과 해석 구분

| 구분 | 내용 |
|---|---|
| 화면에서 확인했다고 가정한 사실 | 카드 삽입구에는 고정된 초록색 LED만 있다. 또한 광고에 집중한 키오스크로 UX에 의존한 정보전달만을 하고있다. 그리고 글씨가 광고들에 비해 작은 폰트로 되어있다. |
| 사용자의 관찰 행동 | 사용자가 카드를 두 방향으로 번갈아 넣고 화면과 삽입구를 반복해서 바라본다. 주문하기 버튼을 찾지 못하여 시작화면에서 오랜 시간 머물렀다. |
| 분석자의 해석 | 카드 방향과 삽입 위치를 알려 주는 기표와 대응 관계가 충분하지 않아 사용자가 망설인 것으로 판단한다. 또한 주문하기 버튼의 크기가 작고 광고에 비해 화려하지 않아 헤맨것으로 판단한다. 또한 UX에만 의존한 설계방식으로 처음 접하는 사용자는 사용하기에 힘들기 때문에 시작화면에서 오랜 시간 머물렀다고 판단한다.|
| 아직 확인하지 못한 내용 | 실제 사용자의 시력, 문구 이해 여부, 카드 인식 실패의 기술적 원인, 맥도날드 키오스크 이용 여부. |

## 3. 인터랙션 루프

| 단계 | 사용자 목표 | 사용자 행동 | 시스템 반응·상태 | 사용자가 받는 피드백 | 문제·불확실성 |
|:---:|---|---|---|---|---|
| 1 | 주문하기 버튼 찾기 | 시작 화면을 살펴보고 `주문하기` 버튼을 누름 | 주문이 선택되고 메뉴 선택 화면으로 전환됨 | 주문화면으로 전환됨. | '주문하기' 버튼이 광고에 비해 상대적으로 작고 평범하여 한번에 보기가 어려움. |
| 2 | 메뉴 선택하기 | 먹고싶은 메뉴들을 하나씩 선택. | 사용자가 선택한 메뉴들이 장바구니로 저장됨. | 선택하여 추가된 메뉴들이 장바구니로 들어가는 애니메이션이 빠르게 보여지고 결제 금액만 나오게 됨. | 화면이 단순하지 않고 광고와 함께 많은 정보를 전달하고 있는 UI로 구성되어있어서 소요시간이 많이 소모됨. |
| 3 | 토핑 선택 및 세트 선택하기 | 원하는 메뉴 고르고 단품/세트를 고르고 원하는 토핑을 선택함. | 메뉴 선택화면으로 전환됨. | 선택한 상품의 금액만 추가됨. | 메뉴 이름과 이미지에 비해 원하는 토핑 변경 버튼의 크기가 작고 찾기가 어려움. |
| 4 | 주문확인 후 결제하기 | `주문확인 후 결제하기`를 누르고 추가로 구매할 목록을 선택함. | 사용자가 추가로 원하는 메뉴를 장바구니에 추가함. | 화면에 `함께 즐기시면 좋습니다.`가 표시되고 추천 메뉴가 나옴 | 원하는 메뉴가 없다면 한번의 버튼을 더 입력해야하고 추가 메뉴를 선택하면 이전 루프를 다시 시도해야함. |
| 5 | 주문 완료하기 | 주문내역을 확인하고 자신이 선택한 메뉴가 맞다면 '주문 완료' 버튼을 누릅니다. | 어디서 픽업할지 결정하는 페이지로 넘어가고 테이블이랑 진동벨 번호 선택하고 이후 결제 대기 상태로 넘어간다. | 픽업 장소 지정, 테이블 텐트 및 진동벨 번호 결정 이후 결제화면으로 전환. | 처리 과정이 매우 길고 처음 접하는 단어와 외래어의 혼합 사용으로 인해 사용자의 지속성을 줄입니다. |
| 6 | 결제 완료하기 | 결제 방법을 선택 후, 카드를 뽑고 영수증을 가져감 | 결제 방법 선택 후, 결제가 완료되고 초기 화면으로 돌아갈 준비를 함 | 영수증 출력 안내가 나타남 | 완료 화면이 빨리 사라지면 영수증 위치나 다음 행동을 놓칠 수 있음 |

### 루프 단절 지점

- 가장 크게 멈추거나 망설일 가능성이 있는 단계: `5단계`
- 이유:

> 원하는 모든 메뉴 선택이후에 결제하기 버튼이 상대적으로 작은 글씨에 '주문내역 확인 후 결제하기'로 길게 적혀있어서 클라이언트 입장에서 빠르게 버튼을 확인하고 선택하기에 힘듦. 또한 추가 결제를 유도하는 구간이 길고 과도한 체류시간 증가를 위한 불필요한 페이지의 이동으로 인해 불편함을 초래함. 주문 완료 버튼을 누르더라도 다양한 서비스를 제공하기 위한 페이지들이 주로 이어지며 '테이블 서비스' 및 '테이블 텐트(테이블로 상품 수령), 진동벨 번호 입력' 등의 다양한 서비스 제공 선택 과정으로 인해 과도한 사용자 체류시간과 불편함을 초래함.

## 4. 인터랙션 원칙으로 문제 진단

| 원칙 | 확인 결과 | 해당 | 화면·행동 근거 |
|---|---|:---:|---|
| 가시성(Visibility) | 전체적인 폰트 크기가 작고 광고에 치중된 UI디자인으로 인해 정보전달력이 낮음 | ✓ | 사용자가 원하는 버튼의 위치를 찾기 위해 디스플레이를 오랜 시간 확인함 |
| 행동 유도성·기표(Affordance & Signifier) | 다음 작업의 위치를 애니메이션으로 표시하거나 버튼을 클릭한 이후 손의 위치를 고려하지 않는 UI구조임. | ✓ | 다음 행동을 무엇을 해야할지 고민하고 해당되는 버튼의 위치를 찾음. |
| 피드백(Feedback) | 어떤 상품을 골랐는지 표현되어있지 않고 단순히 총 결제 금액만 적혀있어서 자신이 어떤 메뉴를 담았고 어떤 토핑을 변경했고 몇 개를 구매했는지 한눈으로 확인하기 불편함. | ✓ | 사용자가 이미 구매했던 품목을 다시 장바구니에 담음. |
| 대응 관계(Mapping) | 결제하기 버튼을 누르더라도 실제 결제까지 가는 과정의 단계가 여럿있어서 실제 결제하기 페이지까지의 과정에서 사용자가 착각할 수 있음. | ✓ | 사용자가 결제하기 페이지를 잘못 들어온줄 알고 이전화면으로 돌아감. |
| 제한 사항(Constraints) | 카드를 잘못된 방향으로 넣는 행동을 물리적·시각적으로 예방하지 못함 | ✓ | 반대 방향 삽입이 가능하고 오류가 발생한 뒤에야 알 수 있음 |
| 접근성(Accessibility) | 작은 글씨와 시각 중심 안내가 저시력 사용자에게 불리함 | ✓ | 작은 글씨들로 인해 체류시간이 길어지고 아무 버튼이나 누르게됨. |

|:---:|---|---|---|---|---|

## 5. 핵심 문제 진술

> 기본적인 키오스크의 사용 경험이 있더라도 뒤에 기다리는 다른 고객이 있는 상황에서 빠른 시간내에 결제를 완료해야하는 상황이라면, 화려한 광고 속 작은 '주문하기' 버튼을 누르고 원하는 메뉴를 선택후 어떤 메뉴를 선택했는지는 합계금액으로만 나오기에 기억력에 의존해야만 한다. 또한 토핑이나 메뉴 변경 버튼의 크기가 작고 메뉴의 이름과 그림에 시선을 빼앗겨 변경 버튼을 무시하고 지나가기에 좋은 상황이다. 또한 결제하기 이후에 고객이 선택해야하는 서비스가 지속적으로 존재하여 같은 과정을 반복하는 일이 발생한다.
### 근거 수준

- ☑ 수업용 가상 화면·행동 시나리오에서 확인한 내용
- ☑ 실제 맥도날드에서 직접 관찰한 사실
- ☑ 실제 발생 빈도와 영향 정도는 아직 검증하지 않은 추정

추가로 확인해야 할 정보:

> 고령층의 맥도날드 키오스크 사용량 이외에도 키오스크를 많이 사용해보지 않은 고객들의 주문하기 버튼 찾기, 메뉴 변경, 결제하는 과정에서 발생하는 문제상황의 발생 수준 검토를 위한 조사가 필요. 또한 다른 햄버거 프랜차이즈점의 해당 문제 발생 비율을 조사하여 문제 발생률을 비교.

| 핵심 문제 | 제안한 설계 변화 | 기대하는 사용자 행동 변화 | 위험·부작용 |
|---|---|---|---|
| 토핑 변경 버튼, 음료 변경 버튼 등을 찾기 어려움 | 상대적으로 작은 버튼들의 크기를 증가시키고 상품의 글씨와 크기는 줄이고 해당 버튼들의 폰트 사이즈 키우기 및 강조효과를 위한 애니메이션 구현 | 고객이 원하는 토핑을 변경하고 먹고싶은 음료를 선택하기에 용이함 | 상품의 글씨와 크기를 과도하게 줄이고 상대적으로 버튼의 크기가 커지게되면 반대로 고객이 어떠한 상품을 구매했는지 확인하기 어려움. |
| 결제하기 버튼 이후의 과정이 길고 소비자가 고민하고 선택해야하는 단계가 필수적으로 들어가있음 | 서비스의 기본값을 설정하고 원하는 사용자만 해당하는 서비스를 선택할 수 있는 화면으로 이동한다. | 과정의 단순화로 소비자가 고민해야할 부분을 줄이고 빠른 주문과 결제로 추후 소비자의 재방문률을 높인다. | 과정의 단순화로 인해 원하는 서비스를 고르지 못 하여 발생하는 기존 고객의 불편함 발생. |

### 검증 가능한 가설

> 적절한 버튼의 크기와 위치를 조절하고 전체적인 크기의 조절과 과정의 단순화를 적용한다. 또한 이후 행동의 예측을 애니메이션과 강조효과를 통해 명확히 설명하면 맥도날드 키오스크에 익숙하지 않은 고객에게도 효과적으로 적용되어 평균 주문시간 단축과 이전 단계로 돌아가는 상황이 줄어든다.

## 8. 개인 성찰

### 8-1. 처음에는 문제라고 생각했지만 근거가 부족했던 판단
> 처음에는 `고령자는 터치스크린 자체를 조작하는 것을 어려워한다`고 생각했다. 그러나 가상 관찰과 분석을 통해 확인한 진짜 문제는 터치 조작 능력이 아니라, 화려한 광고에 묻힌 작은 '주문하기' 버튼, 찾기 힘든 토핑/사이드 변경 버튼, 그리고 결제 직후 이어지는 복잡한 부가 서비스(테이블 서비스, 진동벨 번호 입력 등) 선택 과정 등 기표와 피드백이 부족한 UI/UX 설계의 문제였다.

### 8-2. 단순화 과정에서 소외될 수 있는 사용자
> 결제 과정을 단순화하기 위해 테이블 서비스나 진동벨 등의 부가 서비스 단계를 '기본값(포장/카운터 수령 등)'으로 넘기거나 숨길 경우, 짐이 많거나 거동이 불편해 직원의 테이블 서비스가 꼭 필요한 사용자(장애인, 노약자, 임산부 등)가 해당 기능을 찾지 못해 소외될 위험이 있다. 

### 8-3. 화면 개선만으로 해결되지 않는 문제
> 매장 내의 심한 소음, 뒤에 길게 늘어선 대기열로 인한 심리적 압박감, 그리고 관찰 상황에 명시된 '키오스크 1대 고장'과 같은 기기 결함이나 매장 환경 문제는 화면 디자인 개선만으로 해결할 수 없다. 오프라인 매장의 하드웨어 유지보수와 혼잡 시 안내 직원의 적절한 배치가 병행되어야 한다.

### 8-4. 다음 평가에서 가장 먼저 확인할 내용
> 개선된 UI에서 사용자가 '사이드 및 음료 변경 버튼'을 헤매지 않고 첫 시도에 바로 찾아 누르는지 확인한다. 또한, 결제하기 버튼을 누른 후 테이블 서비스 선택 과정이 단순화되었을 때, 사용자가 당황하여 이전 화면으로 돌아가는 횟수(루프 단절)가 유의미하게 줄어들었는지를 우선적으로 측정한다.

## 9. 제출 전 자기 점검

- ☑ 대표 과업의 시작과 완료 상태가 명확하다.
- ☑ 인터랙션을 시간 흐름에 따라 6단계로 기록했다.
- ☑ 시스템 상태와 사용자가 지각하는 피드백을 구분했다.
- ☑ 문제를 사용자 행동과 화면 근거로 설명했다.
- ☑ 핵심 문제 진술에 해결책을 포함하지 않았다.

- ☑ 가설에 사용자, 과업, 지표, 기준값, 목표값이 포함된다.
- ☑ 정량 지표와 정성 평가 질문을 포함했다.
- ☑ 접근성과 예외 사용자를 고려했다.
- ☑ 모든 수치를 가상값으로 표시했다.
